# Pyxis

A single-player mobile game about charting a dead frontier: salvage-cartography
with a cyberpunk accent, built in **Godot 4.6** for portrait phones (720×1280
base viewport).

You fly a survey vessel out past the edge of the charted volume, crack derelict
hulls, read what you pull out of them, and sell charts of places nobody has
filed a return from. The further out you go the better it pays and the less
anyone is watching — which is the trade the whole game rests on.

### The harnesses

There is no test framework. Every check is an assertion inside `main.gd`, gated
behind a `PYXIS_*` environment variable and run headless:

```bash
PYXIS_LOGTEST=1 /Applications/Godot.app/Contents/MacOS/Godot --headless --path .
```

Each prints `[tag] NAME <measurements> -> PASS|FAIL`. There are 54 of them —
the 54 tags in `run_harness.sh`'s `TAGS` — plus `SAVETEST`, which is **not** in
`TAGS` at all: it is one harness with 23 stateful modes, run as its own
sequence. So a full sweep is 54 + 23 = **77 runs**.

Those three numbers are derivable from `run_harness.sh` and nothing else, so
check them there rather than trusting this paragraph — it has been wrong before,
in two places that disagreed with each other (STRATEGY §73).

**`tools/run_harness.sh` now runs this check for you** and refuses to start the
sweep if it fails, so the version below is only for checking a change by hand
before you commit it.

**Before running one, check that it parses.** Two gates do this, and
`run_harness.sh` runs both for you in this order:

```bash
tools/check_scripts.py     # static, no Godot needed, names the LINE
```

The first is `tools/check_scripts.py`, plain Python against every `.gd` file.
It is strictly weaker than Godot's parser and exists anyway, for the error
message: a mis-indented block in `deep_space.gd` is reported by Godot as
`Could not parse global class "DeepSpace"` plus four hundred cascade lines in
files nobody touched, an autoload that will not compile and a boot that fails —
the actual line appears nowhere in it (STRATEGY §77). It catches two things:

- a block opener whose body is not indented under it — **a comment is not a
  body**, and since every block here opens with a paragraph, the explanation
  sits exactly where the body should be and the eye reads it as the block;
- `SomeClass.member` naming something that class does not declare.

It also runs where Godot is not installed, which is the case that let the
defect it was written for reach `main` in the first place.

The second is Godot's own parser — 0.6 seconds against a 7-minute silent hang.
Bind the binary to a variable and **prove it exists first**:

```bash
GODOT=/Applications/Godot.app/Contents/MacOS/Godot

"$GODOT" --version && "$GODOT" --headless --path . \
  --check-only --script scripts/main.gd 2>&1 | grep -c 'Parse Error'
```

That command **always exits 0**, so the count is the signal, not the exit
status. It matters because a `main.gd` that fails to parse does not error — the
harness never dispatches, the game boots normally, and it runs forever. A broken
run and a slow one look identical, and one sat for four hours before anybody
checked (STRATEGY §69).

**The `--version &&` is not decoration, and neither is `$GODOT`.** `godot` is
usually *not* on `PATH` on macOS — the binary lives inside the `.app` bundle, and
`run_harness.sh` has always defaulted to the full path rather than the bare name.
Run the check with a bare `godot` and the shell writes `command not found` to
stderr, `2>&1` pipes that into `grep`, and it counts **zero** occurrences of
"Parse Error" and prints a confident `0`. The gate reports a clean parse when the
compiler never ran, which is worse than no gate at all — and it is how a sweep
was once launched against a project whose class registry had never been rebuilt.
Short-circuiting on `--version` means a missing binary prints nothing rather than
a lie.

The same trap has a second door: **a new `class_name` needs `--import` before
this check means anything** (see the import note further down). Without it the
failure is `Could not find type "X"` rather than `Parse Error`, which the grep
above does not match — `run_harness.sh`'s built-in check greps for all three
strings for exactly that reason.

The house rules, learned the hard way and enforced by review:

- **Assert the rule, not the rendering.** Test the thing that must be true once,
  rather than each of the three places it is displayed.
- **When a value holds by luck, assert the invariant, not the instance.** A test
  naming one pair stops being a test the moment somebody adds a third.
- **An assertion is only worth what it can see.** More than one defect has
  shipped in code written specifically to prevent that class of defect.
- **Verify a new assertion in both directions** — it should go red when the bug
  it describes is reintroduced. One that passes on broken code is worth nothing.

### The sweep

```bash
tools/run_harness.sh              # every harness
tools/run_harness.sh DEEPTEST     # just these tags
```

It runs every harness in sequence, counts PASS/FAIL and script errors — a
crashed run prints fewer PASS lines but no FAIL, so counting PASS alone would
call it clean — and md5s `save.json` before and after to prove no harness wrote
the real save. `SAVETEST` is stateful: `=write` and the bare read run in that
order and as a pair, which the script's ordering guarantees. Exit status is 0
only if all three checks pass.

Not in the sweep, on purpose: `PYXIS_WORLDTOUR`, `PYXIS_DEMO`, `PYXIS_ECONDEMO`
and the `*SHOTS` modes assert nothing, and WORLDTOUR never calls `quit()` unless
`PYXIS_SHOTS` is set. `PYXIS_TITLETEST`, `INPUTTEST`, `DOCKTEST` and
`MARKETTEST` print `[tag]` observations for reading rather than PASS lines;
they run, but contribute 0 to the count. `TUTORIALTEST` used to be in that
list, and its one promoted line — `WORLD REOPENED` — immediately failed and
exposed a tutorial that could not be finished (STRATEGY §54). The others are
candidates for the same treatment.

A fresh clone or worktree has no `.godot/` import cache, and several harnesses
running at once will race to build one and fail to load every WAV. Import once
first:

```bash
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --import
```

**Run that after pulling a change that adds a new `class_name`, too** — not just
on a fresh checkout. The class registry lives in
`.godot/global_script_class_cache.cfg` and is rebuilt only by an import pass, so
until one runs the new type does not exist. `main.gd` declares a member of most
of them, so the failure is not subtle: the project refuses to load at all, with
one `Could not find type "X"` followed by a cascade of `Cannot infer the type of
…` from every expression that touched it.

That cascade is the tell. If a pull leaves you with a screenful of parse errors
naming one unfamiliar type and then a lot of inference failures, this is it —
`ManualScreen`, `Hunt` and `HoldScreen` each caused exactly that on the way in.

### The assertion the relocation recalibrated — and its fourth version

`PYXIS_BALANCE`'s `PHASE INTEGRITY` has two clauses. The floor — **every run
engages at least one seal** — has never once read zero across 66 measured fight
samples; it encodes the actual design catastrophe ("a fit that bursts through
would never meet a seal") and it is unchanged.

The second clause used to be **every fit's median is at least two**, and the
relocation broke it honestly: a fight staged at the lair, 300u+ out, has no
swarm waves in it (they are charted-space pacing, and `_process` returns early
on them past the chart edge), so phases go down faster and fits meet fewer
seals than every earlier calibration of the bar was taken against. The
measurement pass that §39 deferred (five standalone runs, pooled with the
relocation pass's samples — 66 in all) put numbers on it: 18-29% of the low
fits' mass sits at exactly 1 seal — PULSE 4/14, TORP 3/13, TORP+LNC 2/10,
LANCE 2/11. A median-of-three bar at 2 against that mass fails
P(≥2 of 3 samples = 1) ≈ 43% of sweeps, which is precisely the observed
"failed 3 of 5 runs, standalone and in-sweep alike." The bar was resting on the
distribution's own median; no amount of resampling fixes the wrong statistic.

The fourth version asserts what the 66 samples actually guarantee: **every fit
lands at least one run of ≥ 2 seals**, resampling *until* one lands, capped at
five samples. The longest observed run of 1s is two; five straight is ~0.2% at
the worst fit's measured rate, so residual flake moved from ~43% to ~0.3% — by
changing the claim to one the distribution supports, not by loosening it.
Whether a typical 1-2 seal deep fight *feels* right is a playtest question,
kept deliberately out of this line. STRATEGY §41.

`PYXIS_BALANCE` fights the apex to a conclusion with six fits — resampling any
fit whose first run engages fewer than two seals until one run does, capped at
five samples per fit — and has taken anywhere from five to twenty minutes
depending on how the fights go and what else is running; the runner's
timeout is set well above that, because it exists to catch a harness that never
calls `quit()`, not to police runtime.
