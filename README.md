# Pyxis

A single-player mobile game about charting a dead frontier: salvage-cartography
with a cyberpunk accent, built in **Godot 4.6** for portrait phones (720×1280
base viewport).

You fly a survey vessel out past the edge of the charted volume, crack derelict
hulls, read what you pull out of them, and sell charts of places nobody has
filed a return from. The further out you go the better it pays and the less
anyone is watching — which is the trade the whole game rests on.

## Layout

| path | what |
|---|---|
| `scripts/` | All game code. `main.gd` is the orchestrator and also hosts every test harness. |
| `scripts/data/` | Content as data — systems, modules, commodities, deep-space station archetypes. |
| `docs/STRATEGY.md` | **The canonical design document.** Engine and platform rationale, experience pillars, roadmap, and a numbered record of what shipped and why. |
| `docs/HORIZON-3-COMMISSION.md` | The next piece of work: fully specced, adversarially reviewed, not built. |
| `audio/` | Generated by `tools/gen_sfx.py`. |

## Working on this

**Read the relevant `docs/STRATEGY.md` section before touching an adjacent
system.** Most sections record a defect and explain why the current shape
prevents it, so a change that looks like a simplification is often a regression
the doc already argued against.

### The harnesses

There is no test framework. Every check is an assertion inside `main.gd`, gated
behind a `PYXIS_*` environment variable and run headless:

```bash
PYXIS_LOGTEST=1 /Applications/Godot.app/Contents/MacOS/Godot --headless --path .
```

Each prints `[tag] NAME <measurements> -> PASS|FAIL`. There are 34 of them.
The house rules, learned the hard way and enforced by review:

- **Assert the rule, not the rendering.** Test the thing that must be true once,
  rather than each of the three places it is displayed.
- **When a value holds by luck, assert the invariant, not the instance.** A test
  naming one pair stops being a test the moment somebody adds a third.
- **An assertion is only worth what it can see.** More than one defect has
  shipped in code written specifically to prevent that class of defect.
- **Verify a new assertion in both directions** — it should go red when the bug
  it describes is reintroduced. One that passes on broken code is worth nothing.

### The sweep

```bash
tools/run_harness.sh              # every harness
tools/run_harness.sh DEEPTEST     # just these tags
```

It runs every harness in sequence, counts PASS/FAIL and script errors — a
crashed run prints fewer PASS lines but no FAIL, so counting PASS alone would
call it clean — and md5s `save.json` before and after to prove no harness wrote
the real save. `SAVETEST` is stateful: `=write` and the bare read run in that
order and as a pair, which the script's ordering guarantees. Exit status is 0
only if all three checks pass.

Not in the sweep, on purpose: `PYXIS_WORLDTOUR`, `PYXIS_DEMO`, `PYXIS_ECONDEMO`
and the `*SHOTS` modes assert nothing, and WORLDTOUR never calls `quit()` unless
`PYXIS_SHOTS` is set. `PYXIS_TITLETEST`, `TUTORIALTEST`, `INPUTTEST`, `DOCKTEST`
and `MARKETTEST` print `[tag]` observations for reading rather than PASS lines;
they run, but contribute 0 to the count.

A fresh clone or worktree has no `.godot/` import cache, and several harnesses
running at once will race to build one and fail to load every WAV. Import once
first:

```bash
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --import
```

Current baseline: **398 PASS / 1 FAIL / 0 script errors** across 51 runs, save
format **v15**. The one FAIL is `PYXIS_BALANCE`'s `PHASE INTEGRITY`, and it is a
**stale threshold rather than a regression** — see "the assertion the relocation
recalibrated" below. Every other suite is green. The 399 are the 268 that
shipped, plus `PYXIS_FEELTEST` (13),
`PYXIS_UITEST` (14), `PYXIS_GSATEST` (17), `PYXIS_ACCESSTEST` (11),
`PYXIS_MINETEST` (25), `PYXIS_ENVTEST` (9), `PYXIS_STREAMTEST` (6), two more in
`MUSICTEST` for the score's depth axis, two more in `CARTTEST` for the mast's
clearance, one more in `LIVERYTEST` for the earned ninth accent, two in
`SAVETEST=migrate12` for the v12→v13 migration, and three in
`SAVETEST=migrate13` for v13→v14, and `PYXIS_HUNTTEST` (13) with
`SAVETEST=migrate14` (3) for v14→v15.

Mining stages 2 and 3 added seven: three in `MINETEST` (the fit reaching the
verb, the power a mining commit costs, and the survey mast deferring a reading
it cannot take whole), three in `PACINGTEST` for the prospector's route profile,
and one in `SHIPTEST` that no mining module is invisible in the refit console.
Neither stage touched the save.

Mining stage 4 added ten and bumped the save to **v14**: seven in `MINETEST`
(the charted eleven as a windfall, the persistent/session split, that the skill
is fed by cuts and never by sales, that no tier buys credits, that a core sample
can never out-yield a cut, and the two access tiers), and three in
`SAVETEST=migrate13` (a v13 save arrives unmined, `seams_cut` survives a round
trip, and the validator rejects a hand-edited key).

The Hunt stage 2 moved the apex engines out into the expanse and added six
assertions, no save bump: five in `PYXIS_HUNTTEST` (the arena keep-out is
`ApexBoss.LEASH_RANGE` and cannot drift from it, the keep-out subtracts and only
inside itself, it never reaches `MINETEST`'s world fingerprint, nothing but rocks
and seams is left in the arena, and the leash ends the fight *only* past the
leash) and one in `PYXIS_RADARTEST` (the engine is not on the map until you are
inside `DETECT_RANGE`). `DEEPTEST` 30 was inverted rather than added to — the
chart edge no longer breaks a fight off, so it now asserts the lock **holds** at
depth. `APEXTEST`'s `grav_tether` check was briefly a printed observation —
re-staging it exposed a defect it could never have caught, and the tether had
dragged an idle ship 0.0u since the day it shipped. That defect is now fixed and
the clause is a real assertion again, joined by a second one that the weakest
legal fit can still burn free of a live tether. STRATEGY §40.

`PYXIS_MANUALTEST` (6) covers the in-game pilot's manual: that every contents
entry opens a real page, that opening and closing it never moves the pause state
from either a running or a stopped tree, that CANCEL backs out one step rather
than resuming the game underneath, that its numbers still agree with the data
they came from, that its band swatches recolour with the colour-vision modes, and
that the sheet's scroll viewport is exactly `min(content, room)` on every page.
That last one is deliberately **not** written as "the panel fits the screen" —
see STRATEGY §37 for why that shape cannot fail, and for the deferred-`queue_free`
bug that rewriting it uncovered.

Harness state is **pinned**: `Main._ready()` calls `reset_to_starter()` whenever
any name in `HARNESS_VARS` is set, then pins `run_seed` to `RUN_SEED_PINNED` so
the hunt hides its lairs in the same place on every run. Before the pinning,
every assertion was measured against whatever was in the developer's `save.json`,
and three of them went red the first time anyone actually played the build. See
STRATEGY §33.

**Adding a harness means adding it to `HARNESS_VARS` too.** `PYXIS_MINETEST` and
all three capture modes were dispatched and swept while absent from that list —
so they ran unpinned for horizons, and a refit capture came back photographing
the developer's own ship. `THE PINNING LIST IS COMPLETE` in `PYXIS_HUNTTEST` now
reads `main.gd` and fails if the two lists disagree. See STRATEGY §38.

### The assertion the relocation recalibrated

`PYXIS_BALANCE`'s `PHASE INTEGRITY` has two clauses. The floor — **every run
engages at least one seal** — holds in all thirty fight samples measured across
five runs; it never once read zero, and it is the clause that encodes the actual
design catastrophe ("a fit that bursts through would never meet a seal").

The second — **every fit's median is at least two** — no longer describes the
fight it samples. Swarm waves are charted-space pacing and `_process` returns
early on them past the chart edge, so a fight staged at the lair, 308u out, has
**no waves in it at all**. Every earlier calibration of that bar was taken from
fights that did. Without the incidental targets the phases go down faster and
the fit meets fewer seals, and the bar now sits inside the noise for four of the
six fits. Measured, seals per fit:

    LANCE     2, 2, 2, 1, 1, 2      MIXED     2, 3, 3, 4
    ARC       5, 4, 10, 3           TORP      3, 1, 3, 1, 4, 2
    PULSE     2, 2, 1, 1, 3, 2      TORP+LNC  2, 2, 1, 1, 2

Three of five runs failed it, on four different fits, standalone and in-sweep
alike. **This is a threshold to re-derive, not a bug to chase** — and deliberately
left for a measurement pass rather than nudged here, because this suite's own
comments record two previous rewrites caused by exactly that: a bar set from too
few samples of a distribution nobody had measured. STRATEGY §39.

`PYXIS_BALANCE` fights the apex to a conclusion with six fits — plus up to two
resamples each, for any fit whose first run engages fewer than two seals — and
has taken anywhere from five to twenty minutes depending on how the fights go
and what else is running; the runner's
timeout is set well above that, because it exists to catch a harness that never
calls `quit()`, not to police runtime.
