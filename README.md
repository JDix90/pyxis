# Pyxis

A single-player mobile game about charting a dead frontier: salvage-cartography
with a cyberpunk accent, built in **Godot 4.6** for portrait phones (720×1280
base viewport).

You fly a survey vessel out past the edge of the charted volume, crack derelict
hulls, read what you pull out of them, and sell charts of places nobody has
filed a return from. The further out you go the better it pays and the less
anyone is watching — which is the trade the whole game rests on.

## Layout

| path | what |
|---|---|
| `scripts/` | All game code. `main.gd` is the orchestrator and also hosts every test harness. |
| `scripts/data/` | Content as data — systems, modules, commodities, deep-space station archetypes. |
| `docs/STRATEGY.md` | **The canonical design document.** Engine and platform rationale, experience pillars, roadmap, and a numbered record of what shipped and why. |
| `docs/HORIZON-3-COMMISSION.md` | The next piece of work: fully specced, adversarially reviewed, not built. |
| `audio/` | Generated by `tools/gen_sfx.py`. |

## Working on this

**Read the relevant `docs/STRATEGY.md` section before touching an adjacent
system.** Most sections record a defect and explain why the current shape
prevents it, so a change that looks like a simplification is often a regression
the doc already argued against.

### The harnesses

There is no test framework. Every check is an assertion inside `main.gd`, gated
behind a `PYXIS_*` environment variable and run headless:

```bash
PYXIS_LOGTEST=1 /Applications/Godot.app/Contents/MacOS/Godot --headless --path .
```

Each prints `[tag] NAME <measurements> -> PASS|FAIL`. There are 34 of them.
The house rules, learned the hard way and enforced by review:

- **Assert the rule, not the rendering.** Test the thing that must be true once,
  rather than each of the three places it is displayed.
- **When a value holds by luck, assert the invariant, not the instance.** A test
  naming one pair stops being a test the moment somebody adds a third.
- **An assertion is only worth what it can see.** More than one defect has
  shipped in code written specifically to prevent that class of defect.
- **Verify a new assertion in both directions** — it should go red when the bug
  it describes is reintroduced. One that passes on broken code is worth nothing.

### The sweep

```bash
tools/run_harness.sh              # every harness
tools/run_harness.sh DEEPTEST     # just these tags
```

It runs every harness in sequence, counts PASS/FAIL and script errors — a
crashed run prints fewer PASS lines but no FAIL, so counting PASS alone would
call it clean — and md5s `save.json` before and after to prove no harness wrote
the real save. `SAVETEST` is stateful: `=write` and the bare read run in that
order and as a pair, which the script's ordering guarantees. Exit status is 0
only if all three checks pass.

Not in the sweep, on purpose: `PYXIS_WORLDTOUR`, `PYXIS_DEMO`, `PYXIS_ECONDEMO`
and the `*SHOTS` modes assert nothing, and WORLDTOUR never calls `quit()` unless
`PYXIS_SHOTS` is set. `PYXIS_TITLETEST`, `TUTORIALTEST`, `INPUTTEST`, `DOCKTEST`
and `MARKETTEST` print `[tag]` observations for reading rather than PASS lines;
they run, but contribute 0 to the count.

A fresh clone or worktree has no `.godot/` import cache, and several harnesses
running at once will race to build one and fail to load every WAV. Import once
first:

```bash
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --import
```

Current baseline: **360 PASS / 0 FAIL / 0 script errors** across 47 runs, save
format **v13** — the 268 that shipped, plus `PYXIS_FEELTEST` (13),
`PYXIS_UITEST` (14), `PYXIS_GSATEST` (17), `PYXIS_ACCESSTEST` (11),
`PYXIS_MINETEST` (15), `PYXIS_ENVTEST` (9), `PYXIS_STREAMTEST` (6), two more in
`MUSICTEST` for the score's depth axis, two more in `CARTTEST` for the mast's
clearance, one more in `LIVERYTEST` for the earned ninth accent, and two in
`SAVETEST=migrate12` for the v12→v13 migration.

Harness state is **pinned**: `Main._ready()` calls `reset_to_starter()` whenever
any name in `HARNESS_VARS` is set. Before that, every assertion was measured
against whatever was in the developer's `save.json`, and three of them went red
the first time anyone actually played the build. See STRATEGY §33.

`PYXIS_BALANCE` fights the apex to a conclusion with three fits and has taken
anywhere from five to eleven minutes depending on how the fights go; the runner's
timeout is set well above that, because it exists to catch a harness that never
calls `quit()`, not to police runtime.
